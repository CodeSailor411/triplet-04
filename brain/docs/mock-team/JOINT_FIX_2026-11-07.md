## Answer to Dali: SH-05 and action caps

Brain reads `get_capabilities.action_caps` when a peer explicitly supplies it and otherwise reads `list_actions.actions[].domain/action_cap`. Current Twin does not expose `action_caps` through capabilities. Its manifest has actions for Traffic, Water, Power and Emergency; Air Quality has no actuator and no action row.

SH-05 belongs to **traffic and air_quality**. Twin counts the target in both domains, but its sensor-only Air Quality domain has `action_cap=null`: there is no action cap to exceed for that domain. Previously Brain treated the missing Air Quality action row as unknown and returned `CAP_UNAVAILABLE` before authorization.

Brain now recognizes that null-cap convention only from complete, consistent discovery: the node count matches the complete node list, actuator fields are present, the configured domain appears in the manifest's domain roster, standalone nodes are sensor-only, and shared-node actuators all resolve to their advertised manifest/carrier/domain. Isolation-cap numbers are never reused as action caps. Incomplete or unknown discovery still blocks. Explicit finite caps, including zero, remain enforced for every touched domain; Twin independently enforces the complete request. Missing-cap diagnostics now identify the domain and targets.

## Guardian alignment

No Brain public schema change was needed. The actual Guardian sender successfully discovered and called:

```json
{"notice":{"event_id":"<stable event id>","run_id":"<Twin run id>","state":"quarantined","device_ids":["SH-05.congestion_index"],"reading_ids":[]}}
```

Required fields: `event_id`, `run_id`, `state`, `device_ids`; `reading_ids` defaults to `[]`. States: `isolated`, `quarantined`, `corrected`, `released`. Guardian uses `BRAIN_MCP_URL` and `BRAIN_GUARDIAN_CALLER_KEY`; the key must equal Brain's setting with the same name. An ACK means evidence invalidation, never a containment action by Brain. Repeated event IDs are acknowledged without replay; state remains in memory.

The generated `houssem.env` now includes `BRAIN_TIMEOUT_SECONDS=3`. It no longer emits the unrelated optional HTTP webhook key `GUARDIAN_BRAIN_BEARER_KEY`. Guardian's own SSE runner calls `brain_config()` at startup and refuses an orphan webhook key without `BRAIN_VERDICT_URL`. Re-running the handover generator removes that invalid orphan setting from an old generated role file while preserving existing Brain credentials. A separately configured complete webhook pair is preserved. No pushed-score webhook is required by Brain.

S02 keeps Brain's exact `WAT-01`, `position:40` preview before Guardian approval; Twin enforces caller-scoped preview validity and single use. This validates a virtual command, not hydraulics. S05 keeps the medical incident and current ambulance availability IDs, discovered carrier, incident destination and one-unit request. No trust cutoff, signature, preview or evidence check was relaxed.
